Install

Get running in one block

python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,rich]"

chaos-agents plugins                                # see what's registered
chaos-agents run campaigns/demo_echo.yaml --fancy   # zero-dependency smoke test
pytest -q

Or just pip install chaos-bringer from PyPI if you only need the CLI, not the demo campaigns and tests. Point campaigns/demo_proxy_ollama.yaml at a real ollama serve to see the generic proxy hit a live free model instead of the mock.

Core concepts

Four surfaces, one pipeline

Every campaign flows through the same five stages: a Vector crafts a payload, an Adapter delivers it to the target, the result becomes an Observation (reply + tool calls + errors + latency, not just text), a Judge rules on the whole thing, and a confirmed result becomes a Finding — fingerprinted and written to the corpus as JSON Lines.

Each surface is a typing.Protocol, discovered via Python entry-points under a chaos_agents.* group. There's no special case for built-ins: they register through the exact same mechanism a third-party plugin would use.

pass — the target held fail — a confirmed finding inconclusive — target/judge error, not a security result

That third status matters: a target that times out or errors is recorded and the campaign continues — it's never silently scored as either a pass or a leak.

Writing a campaign

One YAML file, fully reproducible

A campaign binds a target (adapter), an attack (vector), and a verdict rule (judge) — each a plugin name plus its config. Nothing is hard-coded; the file is the whole test, reviewable in a diff.

# my_agent.yaml
name: my-agent-secret-leak      # label for reports and the corpus
category: sensitive_data        # optional taxonomy tags (see below);
technique: secret_extraction    #   flow into findings, SARIF rules, ChaosBench

adapter:
  plugin: generic_proxy
  config:
    upstream_url: "http://localhost:11434/api/chat"

vector:
  plugin: static_corpus
  config: {}

judge:
  plugin: rule_based
  config:
    forbidden_substrings: ["sk-my-canary-7788"]   # a leak if this appears

Each block is plugin: (which one) + config: (its keyword arguments — exactly the constructor arguments of the plugin class). See campaigns/ in the repo for one ready-made file per adapter/vector/judge.

CLI reference

Five commands

chaos-agents run CAMPAIGN

Runs the attack, prints findings. Flags: --fancy (Nergal + rich output), --svg PATH (save the fancy report as an image), --no-mascot, --runs-dir DIR, --format {terminal,json,sarif,junit}, --output PATH, --promote DIR (write confirmed findings to a regression corpus), --minimize (shrink each to a minimal reproducer first, with --promote).

chaos-agents bench CAMPAIGN

Scores the target (only the adapter block is used) across the whole ChaosBench suite. Flags: --suite NAME (default chaos-bench-core), --format {text,json}, --output PATH, --min-resilience PCT (CI gate on the score).

chaos-agents regression BASELINE

Re-runs every reproducer in a regression corpus directory (as written by run --promote); exits non-zero if any still fires.

chaos-agents validate CAMPAIGN

Parses the file and confirms every named plugin actually exists — fails fast with an actionable message, without touching the target.

chaos-agents plugins

Lists every registered provider / adapter / vector / judge, built-in or third-party, exactly as discovered via entry-points.

Target adapters — where attacks land

Connects to the system under test

PluginWhat it does
generic_proxyIntercepts any OpenAI/Ollama-shaped chat call. Most frameworks (LangGraph, AutoGen, Google ADK, CrewAI…) need zero adapter code — just point the framework's model client at the proxy.
ollama_chatTalks straight to a local model holding a conversation. Carries state across turns, so multiturn attacks work against it directly.
mcp_faultA fault-injecting MCP proxy — poisons, errors, delays, or mangles tool results on the way back to an agent. Goes deeper with tool-description poisoning (injection in the tools/list reply) and poisoning chains (one tool's output steers the agent into another).
a2aAttacks an Agent-to-Agent agent over JSON-RPC — cross-agent trust abuse, identity spoofing.
chatgpt_appAttacks a ChatGPT App (an MCP server) by calling its tools with hostile arguments.
sandboxA contained world for computer-use agents: a local model acts on a small set of tools, the attack is planted in a page it reads, exfiltration is recorded but never really sent, and compromise is judged from ground truth.
echo / parrotNaive demo targets with no model call — the zero-dependency smoke test and the ChaosBench calibration floor.
Chaos vectors — where attacks come from

Fixed, generated, or evolved

PluginWhat it does
static_corpusReplays a fixed payload list. Zero-cost, no model call, no network.
llmA model writes fresh attacks from a goal you state — no fixed list, varies run to run.
multiturnBuilt-in escalation scripts: a benign opener lowers the guard, later turns push further. Pass your own conversations: to write custom scripts.
indirectBuries the attack inside tool output the agent is asked to process — a poisoned search result, email, or API reply.
mutationFuzzes — multiplies a few seeds into many variants (encoding, authority framing, structure, language). Model-free, a good first stress-test pass.
Judges — what counts as a break

Rule-based or model-read

PluginWhat it does
rule_basedRegex / forbidden-substring matching. No model call, deterministic, the right default for clean cases.
llmA local model reads a plain-English policy and rules on the whole Observation — catches paraphrased leaks and unsafe compliance a rule would miss, still free on Ollama.
Attack taxonomy

OWASP-aligned families and techniques

Every finding carries a category (family) and a technique. They drive fingerprinting, SARIF rule IDs, and ChaosBench's per-family scoring. It's a registry, not an enum — a third-party plugin can validate its own tags against it without importing a rigid type.

goal_hijack

direct · indirect · multi_turn · authority_spoofing · encoded_translated · instruction_collision

sensitive_data

secret_extraction · system_prompt_leakage · memory_context_leakage · cross_user_leakage

tool_misuse

tool_output_poisoning · argument_mutation · unsafe_selection · schema_manipulation

identity_privilege

over_privileged_tool · confused_deputy · agent_impersonation · privilege_escalation

agent_to_agent

malicious_peer · delegation_abuse · message_tampering · cascading_failure

rag_vector

poisoned_document · retrieval_collision · metadata_isolation · embedding_weakness

availability_cost

token_amplification · loops · tool_call_storms · timeout_latency

output_handling

unsafe_structured_output · shell_sql_url_injection · renderer_abuse

supply_chain

malicious_tool_metadata · dependency_model_mismatch

operational (not an attack family)

target_error · judge_error — a slot for non-security outcomes, so they never masquerade as a confirmed finding

ChaosBench

Score any target, comparably

A campaign is one attack against one target. ChaosBench is a fixed, versioned suite of probes across the whole taxonomy, so any agent or model gets a comparable resilience score (overall + per family) and a letter grade. It's model-free and deterministic: each probe tries to make the agent emit a unique sentinel, and a robust agent never does — judged over the whole Observation, so a sentinel leaked into a tool call counts too.

chaos-agents bench campaigns/my_agent.yaml                      # terminal scorecard + live progress
chaos-agents bench campaigns/my_agent.yaml --format json        # machine-readable, for CI
chaos-agents bench campaigns/my_agent.yaml --min-resilience 80  # CI gate on the score

The parrot adapter is the calibration floor — it echoes input back, so it should score near 0%. A hardened agent should sit far above it.

Regression corpus

Catch a fixed vuln coming back

Promote a confirmed finding into a minimized reproducer, then replay the whole corpus later:

chaos-agents run campaigns/my_agent.yaml --promote regressions/ --minimize
chaos-agents regression regressions/

--minimize shrinks the payload to the shortest form that still reproduces the finding, before it's written to disk — so the regression corpus stays a small, fast, meaningful set rather than a growing pile of raw traces.

CI integration

Fail the build on a confirmed finding

This repo ships a composite GitHub Action. A confirmed finding fails the build; the SARIF report lands in your repo's Security tab automatically.

# .github/workflows/agent-security.yml
permissions:
  contents: read
  security-events: write   # for the SARIF upload below
jobs:
  chaos:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - id: gate
        uses: themaker00001/chaos-bringer@v1
        with:
          campaign: campaigns/my_agent.yaml
          fail-on-finding: true          # default; false reports without blocking
      - name: Publish findings to the Security tab
        if: always()
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: ${{ steps.gate.outputs.sarif }}

The gate exits non-zero only on a confirmed finding (status=fail) — a target that merely errored is inconclusive and never fails the build on its own. Prefer another runner? chaos-agents run CAMPAIGN --format sarif --output chaos.sarif does the same thing anywhere; the exit code is the gate.

Writing a plugin

No import from this repo required

Implement the method(s) the surface's Protocol asks for — invoke() for an adapter, generate() for a vector, evaluate() for a judge — and register an entry-point in your own package's pyproject.toml:

# in your own package's pyproject.toml
[project.entry-points."chaos_agents.judges"]
my-judge = "my_package.judges:MyJudge"

pip install my-package and chaos-agents plugins picks it up immediately — no subclassing, no import from chaos-bringer at all. The same pattern works for chaos_agents.adapters, chaos_agents.vectors, and chaos_agents.providers.

Full source for every built-in lives in src/chaos_agents/ if you want a working example to start from.
